# 00 · 复习总览与 8 周排期

## 一、目标画像

**岗位**：大数据开发工程师（离线数仓 + 实时计算）
**级别**：3-5 年，中高级 / 资深
**面试形态**：一般 3-5 轮 —— HR 初筛 → 技术一面（八股+SQL）→ 技术二面（项目深挖+场景设计）→ 交叉面/Leader 面（架构+软素质）

**中高级岗位的考察重心**（与初级的区别）：

| 维度 | 初级考察 | 中高级考察（你要准备的） |
| --- | --- | --- |
| 技术 | 会不会用 | 为什么这么用、原理、调优过程、踩坑 |
| 项目 | 做了什么 | 技术选型对比、量化收益、架构演进、权衡取舍 |
| 场景 | 少见 | 给业务场景让你现场设计链路，问容量估算 |
| 软素质 | 少见 | 跨团队协作、推动落地、带人、复盘 |

## 二、8 周路线总览

```
第 1-2 周  ── 离线底盘：Hadoop/Hive/数仓建模/SQL
第 3-4 周  ── 计算引擎：Spark 深挖 + Flink 深挖
第 5 周    ── 实时链路：Kafka/CDC/OLAP/湖仓存储
第 6 周    ── 工程化：调度、数据治理、平台能力
第 7 周    ── 基础补课：Java/JVM/分布式/MySQL/Redis
第 8 周    ── 冲刺：项目复盘打磨 + 模拟面试 + 场景设计题
```

> 每天投入 1-2 小时，周末各 3 小时。总计约 90-110 小时。
> 如果时间被压缩，按下面「精简版」执行。

### 里程碑验收（硬指标）

- **W2 末**：能在 5 分钟内讲清「我们数仓怎么分层的、为什么这么分、维度怎么设计的、遇到过什么建模争议」。
- **W4 末**：能在白板上画出一条完整实时链路（采集 → Kafka → Flink → OLAP → 服务），并回答每一跳的 Exactly-Once 如何保证。
- **W6 末**：能回答「如果让你从 0 搭一套日均 10TB 增量的数仓，你怎么做」，含容量估算、集群规模、成本。
- **W8 末**：完成 4 次模拟面试（1 次 SQL 笔试、2 次技术面、1 次架构面），每次都有复盘记录。

- 周日：周复盘 + 下周预习 + 一次场景设计题练习

## 五、复习方法论

### 5.1 三遍法

1. **第一遍（广度）**：按清单快速过，建立索引，知道「有哪些东西」。每个点 3-5 分钟。
2. **第二遍（深度）**：只攻 ⭐⭐⭐ 和 ⭐⭐，要求能画图、能举例、能答两层追问。
3. **第三遍（输出）**：合上文档，对着题库口述。讲不清的回到第二遍。

### 5.2 费曼检验标准

一个知识点算「掌握」，需同时满足：
- 能用一句话说清它解决什么问题；
- 能画出它的核心流程/结构图；
- 能说出至少一个「不用它会怎样」的反面案例；
- 能说出它的局限性和适用边界。

### 5.3 问题池机制

在 `progress/question-pool.md` 里持续记录讲不清的问题，格式：

```
- [ ] Q: Spark shuffle write 为什么要排序？
  来源: W3D2 | 状态: 二刷 | 关联: docs/04 §3.2
```

每周末清空一次，清不掉的进「面试前必看」清单。

## 六、配套动作（与技术复习并行）

| 事项 | 建议时间 | 说明 |
| --- | --- | --- |
| 简历重写 | W1-W2 | 每个项目按 STAR + 量化收益写，不超过 2 页 |

| GitHub / 博客 | 全程 | 有输出会显著提升简历通过率，哪怕只是几篇源码笔记 |

> **重要**：不要等「全部复习完」再投递。真实面试是最有效的查漏补缺方式，
> 建议 W4 就开始面练手公司。

## 八、心态与节奏提醒

- 复习不是线性的，第 3-4 周通常是最痛苦的「高原期」，此时应该减少新知识点、增加输出练习。
- 面试被问倒是常态，每次面试后 24 小时内写复盘，被问倒的题就是最高价值的复习材料。
- 3-5 年经验的候选人，**项目深度 > 八股广度**。宁可把一个项目讲透，也不要背 500 道八股。
