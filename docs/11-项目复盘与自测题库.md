# 第一部分：项目复盘方法论

## 一、项目介绍黄金结构 ⭐⭐⭐

面试说项目，**控制在 3-5 分钟**，按下面五段式：

```
1. 背景（30s）
   业务是什么、数据规模（日增量/总量/QPS）、团队规模、我的角色

2. 架构（60-90s）
   数据源 → 采集 → 存储/计算 → 服务，用了哪些技术，为什么这么选
   （务必能在白板上画出来）

3. 我的核心工作（60-90s）
   挑 2-3 个最有技术含量的点，每个点讲：问题 → 方案 → 结果
   不要罗列「我写了 XX 张表」，要讲「我解决了什么问题」

4. 难点与亮点（60s）
   最硬的一个技术挑战，完整讲排查过程和量化收益

5. 反思与演进（30s）
   如果重做会怎么改，系统下一步演进方向
   —— 这一段最能体现中高级的思维层次，很多人漏掉
```

## 二、STAR + 量化模板 ⭐⭐⭐

每个项目亮点都用这个模板写成文字稿，反复练到脱稿：

```
【S 情境】业务规模 / 遇到的问题现象
   例：实时大屏 GMV 指标在大促期间延迟从 5s 涨到 3min，且金额与离线对账差 2%

【T 任务】我需要达成什么目标
   例：需要在 1 周内把端到端延迟压回 10s 内，并把数据差异降到 0.1% 以内

【A 行动】我做了什么（技术细节，越具体越好）
   例：① 通过 Flink Web UI 反压监控定位到 keyBy(shop_id) 后头部店铺数据倾斜，
          单 subtask 处理量是均值的 40 倍；
       ② 采用两阶段聚合：先按 shop_id + 随机 64 桶做局部预聚合，再做全局聚合，
          并开启 table.optimizer.agg-phase-strategy=TWO_PHASE；
       ③ 状态后端从 HashMap 换为 RocksDB + 增量 Checkpoint，
          Checkpoint 时长从 90s 降到 12s，size 从 8GB 降到 400MB；
       ④ 金额差异定位为 Kafka 生产端 acks=1 在 Broker 切主时丢消息，
          改为 acks=all + min.insync.replicas=2 + 幂等 Producer；
       ⑤ 建立实时/离线 T+1 对账任务，差异超 0.05% 自动告警。

【R 结果】量化收益
   例：端到端延迟 P99 从 3min 降到 6s；大促峰值 8 万 TPS 稳定运行；
       金额差异从 2% 降到 0.02%；Checkpoint 失败率从 15% 降到 0；
       该方案沉淀为团队实时作业规范，推广到其他 12 个作业。
```

> **量化是核心**。没有数字的项目描述在中高级面试中会被认为「参与不深」。
> 常见可量化维度：数据量、TPS/QPS、延迟（P99）、耗时下降 %、资源/成本下降 %、准确率、故障率、覆盖作业数、影响业务指标。

## 三、必须准备的三类项目 ⭐⭐⭐

| 类型 | 作用 | 举例 |
| --- | --- | --- |
| **深度项目**（1 个） | 二面主攻，能讲 20 分钟不冷场，经得起 5 层追问 | 你最核心、最有技术含量的那个 |
| **广度项目**（2 个） | 展示技术栈覆盖面，各准备 3 分钟版本 | 一个离线数仓 + 一个实时链路 + 一个治理/平台 |
| **失败/踩坑案例**（1 个） | 回答「你遇到过最大的困难」「你的缺点」 | 一次线上数据事故 + 你的复盘与改进 |

> 答不上来的，就是你项目理解不深的地方 —— 这正是面试会挂的地方。

## 五、行为面试题（HR 面 / Leader 面）⭐⭐

| 问题 | 回答要点 |
| --- | --- |
| 为什么离职？ | **不说前公司/领导坏话**。讲发展诉求：业务规模瓶颈、技术栈天花板、想接触更大规模数据/更完整链路 |
| 为什么选我们？ | 提前研究公司业务与技术栈，讲匹配点：规模、技术方向、业务兴趣 |
| 你最有成就感的事？ | 用 STAR，突出**你主导**+量化结果 |
| 你和同事有过冲突吗？ | 讲技术分歧 → 用数据/POC 验证 → 达成共识 → 关系更好。体现对事不对人 |
| 你的缺点？ | 讲真实但不致命的，并说明改进措施（如「有时过度追求方案完美导致排期紧，现在会先做 MVP 再迭代」） |
| 你未来的规划？ | 技术专家路线 or 技术管理路线，讲清 1-3 年目标，与岗位匹配 |
| 期望薪资？ | 提前查行情（脉脉/Levels），给区间，说明可谈，先问对方 band |
| 你有什么想问我的？ | **一定要问**：团队规模与技术栈、业务挑战、这个岗位要解决的核心问题、成长路径、团队怎么做技术评审 |

## 六、简历要点 ⭐⭐⭐
